# Real game vs rumbot, v58 (2026-10-22)

The first 8 seeds of `docs/samples/cloud-lab/seeds-c2k.txt`, each played with `jevbot play --lab --seed S` on the
real game (`--backend balatrobot`, `scripts/launch_fast.cmd`) and on rumbot (`--backend rumbot`). Main at `7b954a2`
(v58), no JEV, no credits. The steps are in `docs/real-game-sync.md`.

## Result

- **The bot made the same choices in every seed.** Seven of 8 seeds made the same accepted actions all the way
  through (104 to 258 actions each). G6MTPMNN made the same choices up to a simulator difference in its last round,
  then still ended where the sim did (ante 8, lost to Crimson Heart). No action differed without a state difference
  before it, so there is **no bot bug**.
- **There are 2 simulator bugs. Each affects the game state, but neither changed an action in these 8 seeds:**
  1. **Crimson Heart releasing Juggler deals a card in rumbot but not in the game** (G6MTPMNN state 101). This changes
     the hand.
  2. **A joker a tag made free shows buy cost 0 in the game but its price in rumbot** (7 of 8 seeds). The sell value
     matches.
- **Joker reordering (`rearrange`, v57): 18 in the real games, all accepted, all identical to the sim**, with the
  same order afterwards.
- **Score estimates (v58): 223 of 297 plays exact (±1%), 23 under, 51 over.** The misses are almost all from jokers
  whose effect is random or not modelled.

## State differences

### 1. Crimson Heart releasing a hand-size joker deals a card in rumbot only (G6MTPMNN, state 101)

- Seed G6MTPMNN, state 101 (ante 8, round 22, SELECTING_HAND, boss Crimson Heart). Field: `hand`.
- Real: 8 cards, hand limit 9. Sim: 9 cards (an extra 9 of Clubs), hand limit 9.
- What happened: Crimson Heart had disabled the Polychrome Juggler (+1 hand size), so the limit was 8. After the
  second hand, the draw filled the hand to 8. Crimson Heart then released Juggler (limit 9) and picked another
  joker to disable. The game deals nothing for the slot Juggler gives back. Rumbot's `set_joker_debuff(false)` goes
  through `_hand_size_changed` (game_jokers.rs:371), which deals 1 card.
- The Lua: `Game:update_draw_to_hand` sets `old_slots`, then `G.STATE = SELECTING_HAND`, and only then calls
  `G.GAME.blind:drawn_to_hand()` (dump `game.lua:3418-3423`). Crimson Heart's release and pick are there
  (`blind.lua:635-660`, `SMODS.recalc_debuff`). The SMODS `CardArea:change_size` deals only when
  `old_slots > total_slots` (`cardarea.lua:116`), and `CardArea:handle_card_limit` only when
  `old_slots < total_slots` (`smods/src/utils.lua:3946-3972`). The fix needs rumbot to model the `old_slots`
  bookkeeping, or at least to not deal when Crimson Heart gives back a hand-size joker in `_drawn_to_hand`.
- The bot then played different cards (accepted action 245). Both runs still lost that boss at ante 8.
- This is new: VENDORED.md covers the Crimson Heart pick (from the v25 identity check), not this deal.

### 2. A joker a tag made free keeps cost 0 in the game (7 of 8 seeds)

- Field: `jokers`, the buy cost of an owned joker. Real 0, sim its shop price. The sell value is the same in both
  (e.g. Onyx Agate: real buy 0 / sell 6, sim buy 12 / sell 6).
- First occurrence per seed: RZSTXX2S state 14 (Negative Onyx Agate), G6MTPMNN state 7 (Polychrome Juggler),
  XKJN7TMN state 3 (Polychrome Sixth Sense), DUQVNM87 state 12 (Negative Vampire), FAXCVJ5M state 27 (Negative Odd
  Todd), D424YXQH state 2 (Foil Faceless Joker), PSUWZ57V state 6 (Polychrome Faceless Joker).
- The Lua: the tag sets `ability.couponed` (`tag.lua:383` and nearby), and `Card:set_cost` makes `cost = 0` for a
  couponed card in the shop (`card.lua:503`). Nothing recomputes the cost after purchase, so the owned joker keeps 0.
  Rumbot reports the price.
- It changed no action here. v50 already has the bot treat cost 0 as "made free", so the sim showing the price
  means sim forecasts see something the real game does not. Rumbot's view should report 0 for a couponed joker.

### Run end after a win (DUQVNM87, FAXCVJ5M, D424YXQH)

- The last state differs in `money` (real 30 / 28 / 43, sim 35 / 44 / 57). After the ante 8 boss is won, the real
  run ends at ROUND_EVAL. The sim lets the bot `cash_out` once more and records that state. The sim's extra action
  is that `cash_out`. Nothing is played after it, so it doesn't matter for results, but the sim run ends one step
  later than the real one.

## Known noise in sync_check

This noise produces sync_check's state-0 difference in every seed, and its action differences in five seeds:

- `hands_left`/`discards_left`/`chips` outside SELECTING_HAND: BalatroBot reports the next round's 4/4 and chips 0;
  rumbot reports 0 or last round's leftovers. The bot doesn't read them there (the 2026-10-19 runs show the same
  state-0 difference).
- A held playing card's buy cost: real 1, sim 0. It is never read.
- Refused `use`: the real game refused 11 consumable uses with `NOT_ALLOWED: Consumable '<name>' cannot be used at
  this time`, in 5 seeds (RZSTXX2S 2, G6MTPMNN 1, XKJN7TMN 1, DUQVNM87 4, FAXCVJ5M 3). Each came right after
  `select` (5, tarots in SELECTING_HAND: The World, The Magician, The Lovers, The Hierophant, The Sun) or right after
  a `pack` action took the game back to the shop (6, in SHOP: Neptune, Pluto, Mars, Uranus, The Hermit,
  Temperance). The bot
  repeated the same action on the next step and the game accepted it. The game was still settling, so this is not
  a decision difference. But sync_check counts the refused action, so every later action index shifts.

The "clean" columns compare the same records with these three removed, and compare an owned joker's sell value
instead of its buy cost.

## Joker reordering (v57)

There were 18 `rearrange` actions in the real games: G6MTPMNN 4, XKJN7TMN 3, DUQVNM87 1, FAXCVJ5M 2, D424YXQH 3,
PSUWZ57V 5, and none in RZSTXX2S or Q5RLLNT9 (the best order was the current one).

- **None was refused.** No `error` follows any of them.
- **Each one left the jokers in the same order as in the sim.** The outcome's joker list after every rearrange is
  identical, and the sim sent the same permutation at the same point.
